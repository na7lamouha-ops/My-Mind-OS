# وثيقة الصلاحيات — البوصلة

التطبيق = عضو في الفريق، يخدم غير بالصلاحيات اللي يعطيهم التاجر. كل قراءة وكتابة، علاش، ووين تتستعمل.
المسارات كاملين في جدول واحد: `server/tassyir.js` ← `ENDPOINTS`.

## القراءة

| الصلاحية | علاش | وين تتستعمل |
|---|---|---|
| `read_orders` | الليد، المؤكّدة، الموصلة، الروتور، المتروكة، `utm` (الإعلان والزاوية)، `cancellation.reasonLabel`، التواريخ | التأكيد والتوصيل الحقيقيين (الوسط)، رافعة المتروكة، أسباب الإلغاء، أول اتصال، المنحنى |
| `read_products` | السعر، التاغات (المرحلة + المصدر)، المتغيّرات | المحرّك، الفلترة بالمرحلة، احتمال النجاح حسب المصدر |
| `read_inventory` | `Sellable` لكل متغيّر (ولا totalItems − موصّل − في الطريق − خاسر) | الستوك والتعمير، المحبوس، تحذيرات الطلب |
| `read_costs` ⚠️ حساسة | ثمن الشراء/الإنتاج | كل حساب ربح. بلاها: «غير محسوم» ونسقسيو التاجر |
| `read_stores` | المتاجر والعملة | ربط البيانات بالمتجر |
| `read_delivery` | `carrierStatus`، رسوم التوصيل والروتور | رافعة التوصيل، القبض عند شركة التوصيل |

## الكتابة

| الصلاحية | واش نكتبو | الخطر | الموافقة |
|---|---|---|---|
| `write_products` | **التاغات برك.** نقراو التاغات القدام، نحيّو تاغ المرحلة القديم، ونزيدو الجديد (`mergeStageTag`) — حتى تاغ آخر ما يتمسحش | قليل | بلا موافقة، ويتسجّل في تاريخ القرارات |
| `write_orders` | **التعليقات برك**: أسباب الرجوع `#R-01…10`، ملاحظات | قليل | بلا موافقة |
| بيانات التطبيق (App Data) | الخطة، الحدود، العدّادات اليومية، التقارير، بطاقات الموافقة، `webhook-id` المشافين | — | تبقى داخل التطبيق |

## ما يديرهش التطبيق وحدو
تكبير، توقيف عرض، إلغاء، أمر إنتاج، تصفية ← **بطاقة موافقة**. التنفيذ بيد التاجر ولا Tassya. حتى دورو ما يتصرف بلا موافقة. التوقيف ديما مسموح (بلا شروط، بنقرة التاجر).

## Webhooks
`orders/created، confirmed، cancelled، dispatched، delivered، returned، updated` و`inventory_levels/updated`.
موقّعين Ed25519 (`webhook-id`، `webhook-timestamp`، `webhook-signature: v1a,…`). المكرّر يتحيّى بـ `webhook-id`، والانتقال نفسو ما يتعدّش مرتين حتى بـ id جديد.
