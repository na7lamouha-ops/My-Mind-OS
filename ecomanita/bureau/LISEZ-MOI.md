# (historique) v0.3.8 (07/10/2026)

Un bureau d'agents IA pour un e-commerçant COD algérien. Le client colle le **lien Drive de son shooting dans son robot Telegram** ; le robot lui pose les questions avec des boutons ; puis la chaîne part seule : montage, photos, page produit Tassyir (publiée dès qu'elle est prête), campagne Meta EN PAUSE (activée seulement à son « لانسي »), rapport chaque soir, coach, porte du scaling. Tout tourne sur **sa** machine, sur **son** abonnement Claude (Claude Code en mode headless). Aucune clé API, rien chez le vendeur.

- **Trois fonctions de la chaîne du vendeur (15/10/2026, décision « الثلاثة دروك »)**, portées en AJOUT, chacune avec son contrôle (rouge sur l'ancien code, vert sur le neuf) : (1) **le pixel par compte** — « جيب الكونتات » lit en vrai les pixels de chaque compte (`ads_get_datasets`, jeton ou connecteur, relus dans le brut : `pixelsDuBrut`) et les garde dans `comptes[].pixels` ; en mode « site », la fiche Telegram pose « البيكسل » avec les SEULS pixels du compte choisi (huit boutons au plus), un nom tapé n'est pris que s'il est exactement celui d'un pixel du compte, sinon refus et la question revient ; un compte sans pixel propose « بدّل للميساج » ; pixels jamais lus → pas de question (l'ancienne règle) ; la demande porte `pixel: {id, nom}` ; la campagne relit d'abord les pixels du compte (tour `pixel`, lecture seule) : absent → refus, rien créé, la question reposée aux boutons (`mis:<id>:pixel:<i>`) ; présent → la consigne porte cet id, un ad set créé avec un autre pixel est refusé (`fautePixelCreation`). (2) **« الغي » sans fiche** — tapé hors fiche, il ferme TOUTES les questions « لانسي » ouvertes (`annulerPortes` : portes de lot → « refusée », missions seules → `annulee`), sans dialogue, sans aucun tour de Claude (rien activé, rien supprimé chez Meta) ; une porte validée n'est jamais touchée ; le client le lit avec un bouton « سقسيني » par question (`lanceg:<gen>.neuve`, `lance:neuve`). (3) **une seule question « لانسي » à la fois, reprise et garde ensemble** — une porte neuve reprend les modèles prêts des autres questions ouvertes (autres lots, missions seules : `aReprendre` / `fermerReprises`, `porteLot` le dit), une mission seule prête pendant une porte ouverte la fait refaire avec elle (`rejoindrePorte`), pendant la question d'une autre mission seule elle attend (`attendQuestion`) ; LA GARDE (`tenusAilleurs`) : un modèle tenu par la porte d'un autre lot n'est jamais reposé par son lot (le ping-pong de la chaîne du vendeur). Différence avec sa chaîne : chez lui, chaque demande est un lot et la liste des pixels est figée dans le robot ; ici les missions seules gardent leur question d'un modèle, et les pixels sont lus chez le client. Non prouvé en vrai : `ads_get_datasets` sur un vrai compte client (forme lue sur le connecteur et le serveur local), le robot Telegram réel.
- **Page du bureau** : seulement les travailleurs ; les scènes (discussions, cœurs, disputes, espion) derrière le bouton « ورّي الهدرة والضحك ».
- **Cloudflare R2** proposé dès l'installation (repli tunnel sans carte).

## Le mode manuel (v0.3.7) : un agent par discussion
En plus du bureau, le dossier `plugin/` est un plugin Claude Code posé par l'installateur (étape « agents ») : dans une discussion neuve de l'onglet Code, `/ecom-manita:manager` (il enchaîne les autres et dit où en est chaque modèle), `editeur`, `page`, `testing`, `scaling` ou `coach` donne cet agent seul. Chaque skill reprend le métier de l'agent du bureau (`bureau/skills/<agent>/SKILL.md`), adapté au mode manuel (fichiers de commande, codes `MAN`), avec les mêmes règles du vendeur, précédé d'un démarrage et des commandes exactes pour lancer les outils de `outils/` sur la machine (Windows et Mac). Le plugin est chargé en place depuis `ecom-manita/plugin` : un nouveau zip le met à jour. L'installateur écrit le chemin réel du paquet dans `<maison>/paquet.txt` ; les agents le lisent dans `<dossier personnel>/ecom-manita-maison/paquet.txt` (sinon `<dossier personnel>/ecom-manita`). Limite : sur Mac, une maison déplacée par `MANITA_MAISON` avec un paquet hors du dossier personnel n'est pas trouvée par le mode manuel.
Alignés sur le bureau (07/10/2026) : l'éditeur manuel construit un dossier plat (`<lot>_plat`) quand un Drive d'UN modèle est rangé en sous-dossiers de couleurs (après une question au client ; jamais pour un modèle d'un lot, dont le dossier vient déjà plat de la séparation), relance les captures serrées comme le bureau quand il y a moins de six photos, ne refuse jamais une vidéo pour la plaque POV sur le visage (un « A REGARDER » dit au client : la plaque reste en haut) et lit `MONTER-10 --verifier` vidéo par vidéo (une vidéo en ECHEC sort dans `<livraison>_a_supprimer`, le modèle passe avec une vidéo saine au moins et aucune à deux modèles) ; un lot repris après une coupure sort d'abord une livraison inachevée (sans `_rapport-editeur.md`) dans `<livraison>_a_supprimer` avant de la refaire ; l'agent testing manuel vise les mêmes 25 wilayas confirmées (jamais `countries ["DZ"]`) et ne prend jamais une vidéo d'un dossier `…_a_supprimer`.

## Ce que Claude peut faire — et rien d'autre
`claude -p` avec : le prompt système dans un FICHIER (`--system-prompt-file`, Windows limite la ligne de commande à 32 767 caractères), le message par l'entrée standard, `--tools ToolSearch` (aucun shell, aucun fichier, aucun web), `--permission-prompts none`, une liste blanche d'outils PAR ÉTAPE (`--allowedTools`), une sortie JSON imposée (`--json-schema`). Jamais : `dispatch_orders`, `cancel_order`, `deliver_order`, `return_order`, `confirm_order`, aucune suppression.
Les connecteurs du compte claude.ai du client s'appellent `claude.ai <Nom>` dans Claude Code ; la sonde (onglet التحضير → « افحص الكونيكتورات », et la dernière ligne des installateurs) lit `claude mcp list` (Tassyir par son adresse `api.tassyir.io`, Meta par `mcp.facebook.com/ads`, état de connexion vérifié) et l'événement init (leurs OUTILS), et ne garde qu'un connecteur BRANCHÉ. Chaque Claude lancé par le bureau ATTEND ses connecteurs (`MCP_CONNECTION_NONBLOCKING=0`, `MCP_CONNECT_TIMEOUT_MS`, `CLAUDE_CODE_MCP_STARTUP_WAIT_MS`, imposés) : sur un vrai Mac, sans cette attente, l'init partait avant Tassyir et Meta.

## Le dépôt des médias (comment les vidéos montent chez Meta, et s'effacent)
Meta et Tassyir prennent une photo ou une vidéo par une ADRESSE PUBLIQUE (ils viennent la chercher). Le bureau ouvre un dépôt le temps de l'envoi, attend que Meta dise « ready », puis le ferme — rien ne reste en ligne :
| Mode | Compte | Ce qui se passe | Après « ready » |
|---|---|---|---|
| **tunnel** (par défaut) | aucun | un petit serveur de fichiers séparé (liste fermée, chemin secret de 32 caractères) + `cloudflared` (tunnel rapide, adresse `https://….trycloudflare.com`) | le tunnel est fermé : l'adresse meurt |
| **R2** (option) | le compte Cloudflare DU client (carte ou PayPal chez Cloudflare) | envoi signé (SigV4) dans SON bucket, adresse publique `r2.dev` | les fichiers sont EFFACÉS du bucket |

Deux épreuves, dans l'onglet « التحضير » (étape 5) et par l'API :
- « جرّب الدوبو » (`POST /api/depot/epreuve`, et « افحص كلش ») : un fichier au hasard part par l'adresse publique, revient avec la MÊME empreinte (sha256), puis l'adresse doit être MORTE après la fermeture ;
- « ابعث فيديو تجربة لميتا » (`POST /api/depot/essai-meta` `{compte}`, puis `GET` jusqu'à `etat: fini`) : une mire de cinq secondes (FFmpeg, aucune personne, aucune marque) part par le dépôt dans la bibliothèque du compte publicitaire (aucune publicité) ; le `video_id` et « ready » sont lus dans les réponses BRUTES de Meta ; puis le dépôt ferme et l'adresse doit être morte.

## La vie du bureau (la page `http://localhost:4620/`)
Par défaut, la page ne montre que les travailleurs et l'état réel des tâches ; les discussions entre collègues, la comédie du bureau (le Boss, ريم, الحلّاب, شيكم) et les licenciements ne jouent qu'après le bouton « ورّي الهدرة والضحك » (choix gardé dans le navigateur). Avec ce bouton, le bureau isométrique vit : dix agents toujours en marche (la chaise reste vide quand l'agent se lève), chaque changement d'état d'une vraie tâche fait marcher son agent (manager → poste, poste → Telegram, poste → carnet), deux collègues discutent de leur VRAI travail (ce qu'ils ont fait, ce qui leur manque, lu dans les tâches), le manager rend compte au Boss, le réceptionniste lève la main quand une question attend sur Telegram, et quelques personnages (le Boss, ريم, الحلّاب, شيكم) jouent la comédie du bureau. Une vraie tâche en échec fait venir le Boss (un avertissement par faute ; au troisième, l'agent sort par la porte et un nouveau entre). Tout ce qui se dit est gardé chez le client (`bureau-data/bavardages.jsonl`, onglet « الجورنال » → « واش هدرو في المكتب », bouton « نحمّل كامل الهدرة ») ; un seul onglet écrit à la fois (bail côté serveur). Aucune vraie personne : les prénoms sont inventés.

## La maison du client

## Lancer, vérifier, arrêter
```
node serveur.mjs            # → http://localhost:4620
node verifier.mjs           # la barrière (aucun token dépensé)
```
Le chemin normal : le client ouvre l'app Claude, onglet **Code**, environnement **Local**, dossier où est le zip, et colle `MESSAGE-A-COLLER-DANS-CLAUDE.txt` : son Claude décompresse, lance l'installateur dans une fenêtre visible, l'accompagne pour les connecteurs, les comptes, les chiffres, Telegram et la musique, et vérifie tout (`/api/installation/verifier`). Le client ne tape que ses mots de passe.

Sur Windows : `INSTALLER-WINDOWS.bat` installe et démarre ; le raccourci du dossier Démarrage relance le bureau à chaque session ; `ARRETER-ECOM-MANITA.cmd` l'arrête.
Sur Mac : `INSTALLER-MAC.command` installe et démarre ; launchd relance le bureau à chaque session (et après une panne, pas après un arrêt voulu) ; `ARRETER-ECOM-MANITA.command` l'arrête, `DEMARRER-ECOM-MANITA.command` le relance.
Lancés sans clavier (par Claude), les deux installateurs ouvrent la connexion de Claude Code dans une fenêtre à part et l'attendent.

## La boussole du marchand
`http://localhost:4620/boussole/` (lien en bas de l'onglet « التحضير ») : le client tape son objectif, son prix, son achat et son cout de commande Meta ; les couts, les taux déclarés et le dollar viennent des réglages du bureau. Elle rend le cout maximum d'une commande, le chemin vers l'objectif (commandes, confirmées, livrées, retours, pièces à produire), le capital du début et le capital total, le bénéfice, les deux ROI, et — quand le produit perd — les quatre chemins de sortie (cout de commande, livraison, confirmation, prix). Rien ne sort du navigateur du client.
