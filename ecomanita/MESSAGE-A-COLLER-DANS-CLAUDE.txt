RÈGLES
- Après chaque étape, tu vérifies en lisant le résultat réel (un fichier, une réponse du bureau). Jamais « c'est fait » sans la preuve.
- Si une étape échoue : lis l'erreur, corrige la cause, recommence. Relancer l'installateur ne casse rien.
- Tu ne me demandes jamais un mot de passe dans le chat : je le tape moi-même dans la page qui le demande.
- Le jeton de mon robot Telegram, je le colle MOI-MÊME dans la page du bureau, jamais dans le chat.
- Tu ne touches à aucune carte bancaire, tu ne supprimes aucun de mes fichiers.
- Le bureau répond sur http://127.0.0.1:4620 ; toute requête POST vers lui porte l'en-tête « x-manita: 1 ».
- Sur Windows, tes commandes passent par PowerShell : « curl » y est un faux ami. Parle au bureau avec Invoke-RestMethod, par exemple :
  Invoke-RestMethod -Method Post -Uri http://127.0.0.1:4620/api/connecteurs/sonder -Headers @{'x-manita'='1'} -TimeoutSec 200 | ConvertTo-Json -Depth 8
  Avec un corps JSON, ajoute : -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes(($objet | ConvertTo-Json -Depth 8 -Compress)))   (en octets : PowerShell 5.1 abîme l'arabe d'un texte simple)
  Pour un GET : Invoke-RestMethod -Uri http://127.0.0.1:4620/api/reglages | ConvertTo-Json -Depth 8
  Mets TOUJOURS -TimeoutSec 600 sur les POST (comptes, épreuve du dépôt, essai Meta, vérification) : certains prennent plusieurs minutes. Si un appel expire, ne le relance pas tout de suite : relis d'abord l'état (GET) pour voir s'il a fini.

ÉTAPE 1 — Le dossier
Trouve le zip ecom-manita le plus récent. Décompresse-le dans mon dossier personnel : il doit donner <mon dossier personnel>/ecom-manita avec dedans bureau, outils, INSTALLER-WINDOWS.bat et INSTALLER-MAC.command.
- Windows (PowerShell) : Unblock-File "<zip>" ; Expand-Archive -Path "<zip>" -DestinationPath $env:USERPROFILE -Force
- Mac (Terminal) : ditto -x -k "<zip>" "$HOME" ; xattr -dr com.apple.quarantine "$HOME/ecom-manita"
Si un dossier ecom-manita existe déjà : copie d'abord ecom-manita/bureau/config.local.json à côté, et remets-le après.

ÉTAPE 2 — L'installateur (5 à 20 minutes selon internet), dans une fenêtre que je vois
- Windows : Start-Process powershell -ArgumentList '-NoExit','-NoProfile','-ExecutionPolicy','Bypass','-File',('"' + $env:USERPROFILE + '\ecom-manita\bureau\installer\installer-windows.ps1"')
  (les guillemets autour du chemin comptent : un nom d'utilisateur Windows peut contenir un espace).
- Mac : open -a Terminal "$HOME/ecom-manita/INSTALLER-MAC.command"
Dis-moi tout de suite : « une fenêtre va me demander de connecter Claude Code à mon compte : je me connecte et je clique Autoriser ; si on me montre un code, je le colle dans cette fenêtre puis Entrée ».
Lis le fichier ecom-manita/_ETAT-INSTALLATION.txt toutes les 30 secondes et dis-moi en une ligne où on en est. C'est fini quand une ligne commence par « VERDICT: ». Seule la ligne « VERDICT: INSTALLE <date> » est bonne. « VERDICT: INSTALLE AVEC MANQUES » ou « VERDICT: INCOMPLET » = pas fini : lis les lignes ECHEC, corrige la cause, relance la même commande.
L'installateur pose aussi les agents du mode manuel : une ligne qui commence par « agents: » et contient PASSE doit être là. Sinon, lance toi-même : claude plugin marketplace add "<mon dossier personnel>/ecom-manita/plugin" puis claude plugin install ecom-manita@ecom-manita, et vérifie avec claude plugin list (on doit y lire ecom-manita@ecom-manita). Sous Windows, « claude » est $env:USERPROFILE\.local\bin\claude.exe ; sur Mac, ~/.local/bin/claude.

ÉTAPE 7 — Mes vidéos vers Meta : le dépôt
Meta prend une vidéo par une adresse publique. Le bureau la met en ligne le temps de l'envoi, attend que Meta dise « ready », puis l'efface : rien ne reste en ligne. Par défaut, c'est le TUNNEL : sans compte, sans carte, sans abonnement (cloudflared, posé par l'installateur). Cloudflare R2 n'est qu'une OPTION : seulement si le tunnel échoue chez moi, ou si je te le demande.
a) GET http://127.0.0.1:4620/api/reglages : « depot » doit dire "type": "tunnel" (sinon POST /api/reglages avec {"depot":{"type":"tunnel"}}). Puis POST http://127.0.0.1:4620/api/depot/epreuve (jusqu'à deux minutes). Il faut "verdict": "PASSE" : un fichier part par l'adresse publique, revient identique, puis l'adresse est morte.
   Si ÉCHEC : lis "detail". Si mon réseau bloque le tunnel, propose-moi l'option R2 (point b) ; sinon passe à c).
b) OPTION R2 (seulement si a) échoue, ou si je le demande). Demande-moi d'abord, une question : « عندك Visa ولا Mastercard ولا PayPal ؟ ». Cloudflare en exige un pour ouvrir R2, même gratuit ; CIB et Edahabia ne marchent pas. Si NON : on reste sur le tunnel et tu me dis ce qui bloque. Si OUI : guide-moi pas à pas avec le fichier 4-GUIDE-CLOUDFLARE-R2-GRATUIT.pdf (dans le dossier que je t'ai ouvert, sinon dans ecom-manita), une action à la fois, en ouvrant toi-même les pages dans mon navigateur :
     1. https://dash.cloudflare.com/sign-up : je crée le compte et je confirme l'e-mail (je tape MOI-MÊME mon mot de passe).
     2. Storage & databases > R2 > Overview : j'ajoute R2 (je mets MOI-MÊME la carte ou PayPal).
     3. Create bucket : nom ecom-manita-videos (minuscules, chiffres, tirets), classe Standard, le reste par défaut.
     4. Bucket > Settings > Public Development URL > Enable, je tape allow > Allow ; puis Object Lifecycle Rules > Add rule : effacer les objets après 1 jour > Save changes.
     5. R2 > Account Details > Manage (API Tokens) > Create Account API token : Object Read & Write, Specify bucket(s) > Apply to specific buckets only > ecom-manita-videos. La page montre Token value, Access Key ID et Secret Access Key : seules les deux dernières servent.
   Je te donne dans le chat SEULEMENT : l'Account ID (32 caractères, sans https:// ni .r2.cloudflarestorage.com), le nom du bucket, l'Access Key ID et la Public URL complète (https://pub-….r2.dev). Enregistre-les avec POST /api/reglages : {"depot":{"type":"r2","r2":{"compte":…,"bucket":…,"cleId":…,"basePublique":…}}}. La Secret Access Key, JAMAIS dans le chat : j'appuie sur F5, onglet « التحضير », étape 5, je la colle MOI-MÊME dans la case Secret Access Key et j'appuie sur « سجّل ». Relis GET /api/reglages (la clé secrète apparaît masquée : ••••).
   Puis refais POST http://127.0.0.1:4620/api/depot/epreuve : il faut "verdict": "PASSE". Si ÉCHEC avec R2 : lis "detail" (403 = clé ou bucket faux ; « fetch failed » = Account ID mal collé ; « Invalid URL » = Public URL sans https://), corrige avec moi, refais l'épreuve. Si on n'y arrive pas, remets {"depot":{"type":"tunnel"}}.
c) L'essai Meta : POST http://127.0.0.1:4620/api/depot/essai-meta avec {"compte": "<l'id du compte publicitaire que j'utilise, lu à l'étape 4>"}, puis GET http://127.0.0.1:4620/api/depot/essai-meta toutes les 20 secondes jusqu'à "etat": "fini". Si le POST répond "etat": "refuse", ne sonde pas : lis "detail", corrige (le plus souvent : refaire l'étape 4), puis relance le POST. Il faut "verdict": "PASSE" : une mire de cinq secondes (aucune personne) est dans la bibliothèque de mon compte publicitaire, AUCUNE publicité n'est créée, et l'adresse est fermée. Donne-moi le nom de la vidéo (ecom-manita-essai-…) : je peux la supprimer de ma bibliothèque si je veux.
